<p>出口被标记很少是一声巨响，更多时候是一连串很轻的信号：某天登录多要一次验证、订阅页的支付按钮点了没反应、接口开始零星返回 429。单看每一条都能解释成网络抖动，连起来看才是同一个问题在不同阶段的表现。这篇按时间顺序把这些现象排一遍，给出每个阶段可观察的指标和该做的动作，方便你判断自己现在处在哪一段。</p>

<h2>一、标记不是一瞬间完成的，它有几个能观察到的阶段</h2>
<p>平台侧通常不会因为一次请求就判定某个出口有问题，而是把多天内的登录地、设备、请求频率、失败次数累积成一个分数。分数越过某条线后，处置手段会按成本从轻到重逐级施加：先加验证，再限速，最后才是拒绝服务。</p>
<h3>为什么会有先后顺序</h3>
<p>验证的成本最低，对正常用户伤害也最小，所以总是第一步。限速和拒绝对体验破坏大，只有在验证手段压不住时才会启用。理解这个顺序，就能明白为什么早期现象总是软性的。</p>
<h3>同一个出口上的人会互相影响</h3>
<p>如果出口是共享的，邻居的行为会算进同一个地址的分数里。你可能什么都没做，分数却被别人推过了线。这是共享出口最难排查的地方，也是独享出口的主要价值。</p>

<h2>二、最初的十分钟：登录环节先给出信号</h2>
<p>最早期、也最容易被忽略的一组现象都发生在登录前后。它们出现得快、消失得也快，如果不刻意记录，很容易被当成偶发。</p>

<h3>验证从"偶尔"变成"每次"</h3>
<p>平时一周遇不到一次的邮箱验证或图形验证，突然每次都出现，而且换浏览器、换网络依旧。这不是网络问题，而是这个出口或这台设备的信任分在下调。</p>
<h3>已登录会话被提前结束</h3>
<p>正常会话能维持很久，被标记后可能在几小时内被踢出，需要重新登录。频繁被踢是最直观的信号之一，因为它意味着服务端主动缩短了这条会话的寿命。</p>

<h2>三、第一个小时：验证频率与页面行为变化</h2>
<p>跨过验证这道门槛之后，现象会从登录扩散到使用过程。这个阶段的特征是功能还能用，但处处不顺。</p>
<h3>页面加载变慢但网络测速正常</h3>
<p>测速软件显示带宽充足、延迟正常，页面却要转好几秒才出内容。这通常不是链路问题，而是请求在服务端排队或被额外校验，属于典型的软性限流。</p>
<h3>部分功能单独失效</h3>
<p>对话能用，文件上传失败；或者文本正常，图片理解报错。这类"局部坏掉"比整体不可用更值得警惕，因为它说明处置是针对特定能力做的，不是链路断了。</p>

<h2>四、当天之内：订阅与支付开始受阻</h2>
<p>支付是整条链路上校验最严的一环，也是最能反映问题的一环。它同时看卡、看账单地址、看发起交易的网络，任何一项对不上都会失败，而且失败会被记下来。</p>
<h3>支付失败但不提示具体原因</h3>
<p>点了支付，页面转一圈回到原处，没有任何错误码。这种静默失败最常见，通常意味着风控在交易前置环节就拦下了，根本没走到银行。</p>
<h3>连续失败会叠加惩罚</h3>
<p>同一个账号短时间内连续尝试三到五次失败，会被打上支付风险标记，后续即使换卡换网络也可能继续失败。正确做法是失败两次就停手，先排查再试。</p>

<h2>五、三到七天：接口调用的限速与拒答</h2>
<p>如果你是走接口的，现象会更明确，因为有状态码可以看。这个阶段的问题已经不是"慢"，而是"明确告诉你不行"。</p>
<h3>429 与 403 的含义不一样</h3>
<p>429 表示请求过多，通常是频率或并发超限，退避重试往往有效；403 表示没有权限，多半是账号状态或地区限制，重试没有意义。把两者混为一谈，会把时间浪费在无效重试上。</p>
<h3>流式输出中途断开</h3>
<p>长回复生成到一半连接被切断，重发又正常，反复出现。这类现象容易被归因为网络抖动，但在被标记的出口上，它是服务端主动断流的表现。判断方法是换一条干净出口做对照，如果立刻恢复，问题就清楚了。</p>

<h2>六、把现象记成时间序列，判断才不会跑偏</h2>
<p>凭印象判断的准确率很低，因为人只记得最难受的那次。把每天的现象记成一行：日期、出口地址、登录是否要验证、会话是否被踢、接口有无异常状态码。坚持一周，规律自己会浮出来。</p>
<h3>记录表要包含四个字段</h3>
<p>时间、出口地址、现象、当时做的操作。第四项最容易被省略，却最关键——很多"突然出问题"其实是自己刚改过某个设置。</p>
<h3>对照实验能省掉大量猜测</h3>
<p>怀疑出口有问题时，用同一个账号、同一台设备、同一天，换一条干净出口再走一遍相同操作。如果现象消失，问题在出口；如果依旧，问题在设备或账号。这个对照只需要半小时，比反复读经验帖有效。</p>

<h2>常见问答</h2>
<h3>出现验证就说明 IP 被标记了吗？</h3>
<p>答：不一定。验证也可能由异地登录、设备变更、浏览器清理缓存引起。判断方法是看频率：偶发一次属正常，连续多天每次都出现，且换设备依旧，才更像出口侧的问题。</p>
<h3>换一条新 IP 后现象还在，是什么原因？</h3>
<p>答：说明问题的根不在出口。常见原因是设备指纹与登录态没有一起更换，或者账号本身已被单独限制。这种情况下继续换 IP 只会增加变更记录，让情况更复杂。</p>
<h3>429 一直重试会不会自己好？</h3>
<p>答：短时间内不会，反而可能延长限制时间。正确做法是按指数退避拉开重试间隔，同时降低并发，观察一天再恢复原量。持续硬重试是最容易把小问题拖成大问题的做法。</p>
<h3>需要停用账号多久？</h3>
<p>答：没有统一答案，取决于现象严重程度。软性验证类通常观察三到七天，出现持续 403 的建议先停用并核查账号状态与账单，不要在同一天反复试探。</p>
